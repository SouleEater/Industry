# Развёртывание и авторизация

Этот документ описывает, как запустить сервер «Индустрии» для игроков по сети, что в нём защищено и что нужно сделать перед публикацией.

## Что делает сервер

`server/index.mjs` — один процесс Node.js без внешних зависимостей:

- отдаёт единую страницу стола (`dist/table.html`);
- регистрирует и авторизует игроков (логин + пароль);
- хранит пользователей, сессии и партии в SQLite (`node:sqlite`, файл `industry.db` в каталоге данных);
- ведёт столы: комната ожидания на 2–4 человека, старт хозяином, ходы;
- исполняет правила **на сервере** тем же ядром `packages/domain`, что и у клиента: игрок присылает команду, сервер подставляет его место и проверяет ход, клиент только показывает результат;
- рассылает изменения всем за столом через Server-Sent Events (без опроса).

Игра на одном устройстве работает по-прежнему без сервера и без входа. Кнопки входа и «Онлайн» появляются, только если страница открыта с сервера.

## Запуск на своём компьютере

Нужен Node.js **22.13 или новее** (лучше 24) и Python 3 с Pillow и numpy — один раз, чтобы упаковать картинки.

```bash
python -m pip install pillow numpy
npm run table:images     # упаковка картинок
npm run table            # сборка dist/table.html
npm start                # http://127.0.0.1:8080
```

Данные лежат в `./data` (`DATA_DIR`). Сервер по умолчанию слушает только этот компьютер (`HOST=127.0.0.1`).

Проверить с телефона в той же сети: `HOST=0.0.0.0 npm start` (без HTTPS, только для домашней сети).

## Настройки (переменные окружения)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `PORT` | `8080` | порт |
| `HOST` | `127.0.0.1` | адрес; в контейнере `0.0.0.0` |
| `DATA_DIR` | `./data` | каталог базы SQLite и `secret.key` |
| `PUBLIC_ORIGIN` | — | публичный адрес, например `https://industry.example.com`. **Обязательно задайте на хостинге**: по нему проверяется Origin запросов, включаются `Secure`-cookie и HSTS |
| `TRUST_PROXY` | `0` | `1`, если перед приложением стоит прокси (Caddy, nginx): тогда берутся `X-Forwarded-For` и `X-Forwarded-Proto`. Без прокси оставьте `0`, иначе клиент сможет подделать свой адрес |
| `REGISTRATION` | `open` | `open` — любой; `invite` — по коду приглашения; `closed` — регистрация выключена |
| `INVITE_CODE` | — | код для `REGISTRATION=invite`, не короче 6 символов |
| `SESSION_SECRET` | создаётся сам | ключ для CSRF-токенов, не короче 32 символов. На хостинге задайте явно, чтобы токены переживали пересоздание контейнера |
| `SESSION_DAYS` | `14` | срок входа |
| `MAX_USERS` | `500` | предел числа пользователей |
| `MAX_TABLES_PER_USER` | `10` | сколько столов одновременно может вести один игрок |

## Развёртывание на сервере с Docker (рекомендуется)

Нужны VPS с Docker, домен и открытые порты 80 и 443. Сертификат HTTPS получает и продлевает Caddy.

1. Направьте A-запись домена на IP сервера.
2. Скопируйте проект на сервер (`git clone`). Если у вас есть право использовать официальные картинки, положите их в `apps/web/assets/official/` (см. «Картинки издателя» ниже).
3. Создайте настройки:
   ```bash
   cp .env.example .env
   node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"   # вставьте результат в SESSION_SECRET
   ```
   Заполните `DOMAIN`, `SESSION_SECRET`, `REGISTRATION` и `INVITE_CODE`.
4. Запустите:
   ```bash
   docker compose up -d --build
   docker compose logs -f app
   ```
5. Откройте `https://ваш-домен`, зарегистрируйтесь (первым, пока регистрация открыта или по коду), создайте стол и отправьте друзьям ссылку из комнаты ожидания.

Контейнер приложения работает от обычного пользователя, с файловой системой «только для чтения» и без лишних привилегий; порт наружу не публикуется, только через Caddy. Данные лежат в томе `industry-data`.

**Обновление:** `git pull && docker compose up -d --build`. Пользователи и партии сохраняются в томе.

**Без Docker:** `npm start` под systemd/pm2 за любым прокси с HTTPS; выставьте `TRUST_PROXY=1`, `PUBLIC_ORIGIN=https://…`, `HOST=127.0.0.1`. У прокси должна быть отключена буферизация для `/api/tables/*/events` (для nginx достаточно заголовка `X-Accel-Buffering: no`, сервер его уже отдаёт; таймаут чтения поставьте не меньше 60 с).

**Платформы (Render, Fly.io, Railway и подобные):** подойдёт образ из `Dockerfile`. Обязательно подключите **постоянный диск** к `/data`, иначе пользователи и партии пропадут при перезапуске, и запускайте **ровно один экземпляр**: партии обновляются в памяти процесса и ограничения попыток входа тоже.

## Как устроена авторизация

- **Регистрация и вход** по логину и паролю. Логин: 3–24 символа (буквы любого языка, цифры, `_`, `.`, `-`); при сравнении регистр не важен, «Аня» и «аня» — один человек. Пароль: 8–128 символов, простые пароли и совпадающие с логином отклоняются.
- **Пароли** хранятся только в виде хэша **scrypt** (N=32768, r=8, p=1, своя соль у каждого). Открытый пароль нигде не сохраняется и не пишется в журнал.
- **Сессии**: случайный токен 256 бит в cookie `HttpOnly; SameSite=Lax` (и `Secure` с префиксом `__Host-` на HTTPS). В базе лежит только SHA-256 токена, поэтому утечка базы не даёт войти. Срок скользящий (`SESSION_DAYS`). Выход и смена пароля закрывают сессии.
- **CSRF**: все изменяющие запросы требуют заголовок `X-CSRF-Token` (подписанный ключом сервера) и проверяются по `Origin`: чужой сайт запрос не отправит.
- **Перебор паролей**: 8 неудачных попыток на логин и 40 запросов входа на адрес за 15 минут — затем `429`. Регистраций с одного адреса — 6 в час. Ответ на неверный вход одинаков для существующего и несуществующего логина, время ответа выравнивается.
- **Политика безопасности страницы (CSP)** разрешает только скрипты и стили по хэшу (без `unsafe-inline` для скриптов), запрещает встраивание во фреймы и внешние подключения, кроме своего сервера и шрифтов Google. Есть `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, а на HTTPS — HSTS.
- **Честная игра**: сервер сам определяет, чей ход, и подставляет место игрока по его входу (подделать `actorId` нельзя), проверяет ревизию партии, скрывает от игроков порядок колоды и состояние генератора случайных чисел. Настройки стола принимаются только из белого списка; размер запроса ограничен.

**Чего нет:** восстановления пароля по почте (почты в системе нет), входа через Google/GitHub и двухфакторной проверки. Забытый пароль сбрасывает администратор:

```bash
docker compose exec app node server/admin.mjs users
docker compose exec app node server/admin.mjs reset-password Логин   # выдаёт временный пароль
docker compose exec app node server/admin.mjs delete-user Логин
```

Для публичного сервиса с большим числом игроков стоит добавить вход через внешнего провайдера (OAuth) и восстановление по почте; расширять нужно `server/auth.mjs` и клиентский `apps/table/online.js`.

## Резервные копии

Все данные — файл `industry.db` (и рядом `industry.db-wal`) в томе `industry-data`. Надёжная копия на работающем сервере:

```bash
docker compose exec app node -e "const{DatabaseSync}=require('node:sqlite');new DatabaseSync('/data/industry.db').exec(\"VACUUM INTO '/data/backup.db'\")"
docker compose cp app:/data/backup.db ./backup-$(date +%F).db
```

Храните копию вне сервера. `secret.key` (если не задан `SESSION_SECRET`) копируйте вместе с базой.

## Картинки издателя

Иллюстрации карт «Интербеллума», университетов, стартовых предприятий и портреты промышленников взяты из PDF издателя «Мир Хобби»; в правилах сказано, что публикация без разрешения правообладателя запрещена. Поэтому:

- в git эти картинки не входят (`apps/web/assets/official/` в `.gitignore`);
- **публичный сервер с этими картинками — это их распространение**. Если сервер открыт всем, либо получите разрешение издателя, либо собирайте без папки `official`: тогда карты дополнения рисуются схематично, а правила те же;
- для закрытой компании друзей используйте `REGISTRATION=invite` и не публикуйте адрес.

Картинки базовых карт в `apps/web/assets/user-base/` — макеты пользователя; их правовой статус проверьте отдельно перед публичным запуском.

## Ограничения текущей версии

- Один процесс, одна база: горизонтально не масштабируется. Для десятков одновременных столов этого достаточно.
- Ограничители попыток входа хранятся в памяти и сбрасываются при перезапуске.
- Нет таймера хода и автохода за отключившегося игрока: партия ждёт. Разбор лотов, не требующий решения, может запустить любой игрок за столом.
- Из начатой партии выйти нельзя (место остаётся за игроком), брошенные партии удаляются через 60 дней бездействия, пустые комнаты — через сутки.
- Не реализованы режимы «одиночная игра с двумя агентами», «Рост капитала» и пятый игрок.

## Проверка

```bash
npm test     # 270 тестов, из них 23 серверных: вход, защита запросов, столы, ходы, SSE, полная партия
```

Серверные тесты запускают настоящий сервер на свободном порту с временной базой и ходят по HTTP как браузер (cookie, CSRF, Origin).
