# Индустрия — веб-проект

Исследование настольной игры Ивана Лашина и дополнения «Интербеллум», проект ТЗ, чистая архитектура и первый работающий этап.

**Для продолжения работы начните с [PROGRESS.md](PROGRESS.md):** там сохранены решения пользователя, состояние реализации, ограничения, карта кода и ближайшие действия.

Для передачи другой модели используйте [NEXT_MODEL.md](NEXT_MODEL.md): в нём готовая инструкция, порядок следующей разработки и действия для завершения отправки GitHub.

**Статус:** работают два интерфейса. Учебный стол на синтетических картах остался без изменений. Добавлен цифровой стол на настоящем каталоге: 31 предприятие с двумя сторонами, 5 разных стартовых предприятий, 5 промышленников. Полная оригинальная колода ещё не сверена: не хватает пяти пар предприятий, есть расхождения PDF/PPTX. Вдвоём играется против агента базовой игры. «Интербеллум» и сетевой сервер — следующие этапы.

## Открыть приложение

В Windows можно дважды щёлкнуть `START.cmd`, затем открыть [игровой стол](http://127.0.0.1:4173). Или выполнить в этой папке:

```powershell
npm.cmd run dev
```

Нужен Node.js 22 или новее. Внешних npm-зависимостей нет, `npm install` не требуется. Сервер слушает только этот компьютер. Для доступа с телефона понадобятся отдельное развёртывание или настройка локальной сети; текущий адрес на другом устройстве не откроется.

Если порт 4173 занят старым сервером, можно запустить отдельный экземпляр: `$env:INDUSTRY_PORT = '4174'; npm.cmd run dev`, затем открыть `http://127.0.0.1:4174/`. В текущей рабочей сессии новая версия запущена на 4174; процесс старой версии на 4173 Windows не позволила завершить.

```powershell
npm.cmd test          # 216 тестов (плюс тесты интерфейса, если установлен jsdom)
npm.cmd run build
```

Сборка находится в `dist/` и рассчитана на корень домена. В ней есть 72 изображения каталога, но нет ZIP, PDF и исследовательских исходников. [Каталог карт](http://127.0.0.1:4173/apps/web/catalog.html) открывается после запуска сервера.

## Цифровой стол

Отдельный интерфейс, который играет настоящим ядром и настоящим каталогом карт. Собирается в один самодостаточный HTML:

```powershell
npm.cmd run table:images   # только после замены макетов, нужен Python и Pillow
npm.cmd run table          # dist/table.html, около 4.2 МБ
npm.cmd run table:serve    # http://127.0.0.1:4174
```

В Windows можно дважды щёлкнуть `START-TABLE.cmd`: он соберёт стол и запустит сервер.

Файл `dist/table.html` открывается и двойным щелчком, без сервера. Сервер нужен там, где мешает `file://`: сохранение партии между запусками и игра с телефона. Чтобы пустить в стол друзей из той же сети, задайте адрес явно:

```powershell
$env:INDUSTRY_TABLE_HOST = '0.0.0.0'; npm.cmd run table:serve
```

Сервер напечатает адреса, по которым стол виден с других устройств. Он открыт всем в этой сети, поэтому останавливайте его, когда закончите.

Сборка не копирует правила: `scripts/build-table.mjs` читает модули `packages/domain` и `packages/content`, снимает синтаксис модулей и склеивает их с интерфейсом. Источник истины остаётся один. Файл открывается двойным щелчком, сервер для него не нужен.

Что в нём есть: аукцион с расчётом обоих исходов ставки прямо на карточке лота, последовательный разбор лотов, планирование линии, производство по строкам, модернизация, пять промышленников, итог, журнал, каталог карт и локальное сохранение.

Вдвоём третьим участником садится агент базовой игры: бросок d6 выбирает предприятие, затем ставится минимальный легальный диск. Агент не копит экономику, выигранные им предприятия выбывают, люди получают свои компенсации.

Чего в нём пока нет: таймера решения, «Интербеллума» и настоящего сетевого сервера.

**Колода короче коробки.** В каталоге 31 предприятие вместо 36. Втроём этого хватает на все четыре раунда, вчетвером нужно 32, поэтому невыкупленные лоты временно возвращаются в колоду — интерфейс предупреждает об этом при запуске. Мера снимается, когда появятся пять недостающих пар.

## Что уже работает

- 3 или 4 человека на одном устройстве, 4 раунда.
- Ставки дисками 1–4, запрет одинакового значения и своего второго диска на лоте.
- Отдельный учебный режим переменного капитала: оплата углём, 0 и значения выше 9, дополнительный лот без управляющих.
- Последовательное разрешение лотов, добыча/переработка компенсации по выбору игрока.
- Производство, обязательная добыча, необязательные обмены с лимитом, модернизация и учёт использованных карт.
- Подсчёт результата, журнал и локальное сохранение через воспроизводимую историю команд.
- Адаптивный интерфейс и сообщения о недопустимых действиях.
- Планирование линии после аукциона: перемещение карт кнопками, подтверждение каждым игроком и сохранение порядка.
- Вариант «Цепочка»: новые карты вставляются в линию, старые сохраняют взаимный порядок между раундами; производство строго слева направо.
- Выбор при запуске: свободное производство или цепочка, без таймера или 1–3600 секунд на решение. Таймер рекомендательный: уведомляет, не делает ход за игрока и не штрафует.

Это не полная реализация базы: пока нет промышленников и агента для двоих. Доступные режимы специально ограничены, чтобы не запускать некорректную «полную» партию. Цепочка реализована на учебных картах. Таймер отсчитывает одну ставку или компенсацию, а для планирования/производства — весь этап одного игрока. Отсчёт продолжается при перезагрузке и уходе со страницы; часы устройства должны быть корректными. Сетевой контроль времени ещё не реализован.

## Полученные материалы

Исходный ZIP сохранён без изменения содержимого в четырёх файлах `research/archives/base-industry.zip.part001`–`part004`, каждый меньше 50 МБ. Git LFS не требуется. Для восстановления единого `research/archives/base-industry.zip` выполните `python scripts/archive_parts.py` (Python 3.10+, без дополнительных библиотек). Скрипт проверит размер и SHA-256 каждой части и собранного архива. Для запуска приложения и просмотра каталога архив не нужен: изображения и расшифровка уже включены обычными файлами.

`research/base-import-manifest.json` содержит полный список вложений и SHA-256. `packages/content/user-base-catalog.mjs` содержит все расшифрованные карты с номерами исходных слайдов. [Отчёт импорта](docs/06-base-archive.md) объясняет, как повторить обработку и какие данные пока нельзя использовать как подтверждённую колоду.

## Сканы оригинальных компонентов

Место для файлов: **`research/scans/incoming/`**.

[Инструкция к сканам](research/scans/README.md). Можно один PDF. Для предприятий нужны обе стороны; для остальных компонентов — все игровые стороны, весь текст и значки. Все экземпляры сохраняйте в составе скана, даже если иллюстрации похожи.

[Реестр компонентов](research/component-register.json) содержит 86 официальных карточных мест и 15 мест управляющих. Это список для инвентаризации, не готовый игровой контент. Пользовательский каталог содержит 41 расшифрованную запись, но их привязка к официальным экземплярам ещё не завершена: счётчик полностью сверенных компонентов остаётся 0. Для продолжения нужны пять недостающих предприятий базы и материалы дополнения. [Манифест источников](research/source-manifest.json) содержит ссылки, версии и SHA-256 официальных PDF.

## Структура

```text
apps/web/               интерфейс
packages/domain/        чистые правила и переходы
packages/application/   игровой сеанс, сохранение и replay
packages/adapters/      реализация localStorage
packages/content/       учебный пакет и отдельный каталог пользовательских карт
tests/                  тесты правил и восстановления
docs/                   исследование, ТЗ, архитектура, этапы
research/               части исходного ZIP, манифесты, источники и место для новых сканов
scripts/                локальный сервер, сборка, начальный реестр
```

Домен не обращается к браузеру, сети и файловой системе. Каждая принятая команда даёт новую ревизию. Серверная проверка игроков и сокрытие колоды описаны в архитектуре, но сетевой сервер ещё не реализован.
